# Changelog

All notable changes to EDI MapCheck are documented here. This project adheres
to [Semantic Versioning](https://semver.org/) and the format of
[Keep a Changelog](https://keepachangelog.com/).

## [1.0.0] — 2026-07-14

First stable release. EDI MapCheck is a vendor-neutral tool that validates a
**translated output file** against what a **mapping spec** says its **X12
source** should produce — a field-level pass/fail report, in either direction,
across 17 transaction sets. Everything below is exercised by **611 tests** over
a fully synthetic example set.

### Core

- **Field-level validation engine** — spec vs. X12 source vs. translated
  output, categorized findings (value/format/code-translation/condition/
  constant/count/source-data/unmapped), and a meaningful exit code
  (`0` pass · `1` findings · `2` execution error) for CI.
- **17 X12 transaction sets** with declarative, YAML-defined structures:
  810, 812, 844, 845, 846, 849, 850, 854, 855, 856, 867, 940, 943, 944, 945,
  947, 997 — auto-detected from the file's `ST01`.
- **Both directions** — inbound X12 → internal (JSON, keyed flat, config-driven
  SAP IDoc: ORDERS05 / DESADV01 / INVOIC02, plus user-defined layouts) and
  outbound internal → X12.
- **Multi-transaction interchanges** — pair each source transaction to its
  output document by a spec-declared key; per-document and file-level findings.
- **Config-driven output adapters** — add an output format from a YAML
  definition, no Python.
- **Excel spec template** with a strict loader that fails fast with row numbers.

### Workflows

- **Spec import** (`import-spec`) — turn a partner's `.xlsx`/`.csv` mapping doc
  into a native spec, with evidence-based rule classification and a review
  worklist.
- **Partner overrides** (`merge-spec`, `--partner`) — one base spec plus a small
  per-partner delta (add / replace / remove / code-list shadow); every finding
  carries its origin.
- **Regression mode** (`bless`, `regress`) — freeze a known-good run as a golden
  baseline and report only the delta on later runs; nonzero exit on regression.
- **Rule ergonomics** — Format-column `tol:` tolerances, `shift:±Nd/Nw` date
  arithmetic, and `file:` external code-list lookups.
- **Batch / CI mode** (`batch`) — run many checks from a `mapcheck.yaml`
  manifest, emit **JUnit-XML**, aggregate exit codes.
- **Data scrubber** (`scrub`) — mask sensitive X12 element values (names,
  addresses, DEA/HIN/NDC-shaped ids) while preserving structure, lengths, and
  referential consistency; profile-driven, deterministic.

### Reporting & UI

- **Terminal, Excel, and self-contained HTML reports** (`--export-html`) — the
  HTML is single-file, dependency-free, and safe to mail.
- **History trends** (`report`) — pass-rate per spec over time and top recurring
  root causes, in both the HTML export and the Streamlit UI.
- **Streamlit app** — upload three files or use bundled scenarios, filter by
  status, download Excel/HTML.

### Run it anywhere

- **Containerized web app** — `docker compose up` → a browser URL, no terminal.
  `$PORT`-aware for Cloud Run / Render / Railway / Fly.io; image published to
  GitHub Container Registry on release. Streamlit Community Cloud and `pipx`
  install documented.

### Security

- Spreadsheet **formula-injection** neutralized in the Excel export.
- **Decimal-expansion** and **XML-entity-bomb** denial-of-service inputs
  rejected at parse/normalize time.
- Batch runs are resilient — one failing check never aborts the rest.

### Notes

- All bundled example data in `examples/` is **synthetic**, generated by
  `scripts/generate_examples.py`. No proprietary specs or partner data.
- Requires Python ≥ 3.11.
